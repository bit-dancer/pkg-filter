bun test tests/logger.test.ts

## Описание тестов по файлам

### 1. tests/logger.test.ts (20 тестов)

Проверяет модуль логирования:

- **Logger Class**:
  - Создание логгера с уровнем по умолчанию
  - Создание логгера с пользовательским уровнем
  - Логирование debug/info/warn/error сообщений
  - Логирование с контекстом
  - Иерархия уровней логирования
  - Метод http() для HTTP запросов
  - Метод upstreamRequest() для запросов к upstream
  - Методы setStdoutEnabled() и setLogFilePath()

- **Logger Metrics**:
  - Экспорт функций getSuccessfulRequests, getFailedRequests, incrementFailedRequests

- **Default Logger Export**:
  - Проверка экспорта логгера по умолчанию
  - Проверка наличия всех методов

### 2. tests/e2e.test.ts (2 теста)

End-to-end тесты HTTP сервера:

- **Health Check**: Проверка эндпоинта `/health`
- **List Packages**: Проверка эндпоинта `/r/:repo/packages/list`

Тесты запускают реальный сервер и проверяют HTTP ответы.

### 3. tests/paths.test.ts (25 тестов)

Проверяет утилиты работы с путями:

- **Paths Utility**: Проверка определения всех путей (root, config, dataDir, dbPath, reposDir, logFile)
- **getConfigPath/getDbPath**: Проверка функций получения путей
- **normalizePath**:
  - Нормализация корректных путей
  - Удаление начальных слешей
  - Защита от directory traversal (../, %2e%2e)
  - Защита от абсолютных путей с backslash
  - Обработка простых имен файлов и путей с точками

- **validateRepoId**:
  - Принятие корректных ID (буквы, цифры, дефис, подчеркивание)
  - Отклонение некорректных ID (пробелы, спецсимволы, слеши, точки, пустая строка)

### 4. tests/filter.test.ts (25 тестов)

Комплексные тесты фильтрации пакетов:

- **Parser**:
  - Парсинг простой записи пакета
  - Парсинг нескольких записей
  - Сериализация обратно в текстовый формат

- **Filter - Include**:
  - Пустые правила include возвращают все пакеты
  - Include по точному имени
  - Include по RegExp паттерну
  - Include по версии (RegExp)
  - Multiple rules (OR логика)

- **Filter - Exclude**:
  - Пустые правила exclude возвращают все пакеты
  - Exclude по приоритету
  - Exclude debug пакетов по имени
  - Exclude dev и doc пакетов
  - Комбинированные exclude правила

- **Filter - Version Keep**:
  - Оставление N последних версий
  - Пакеты без version-keep остаются неизменными

- **Filter - Dependency Resolution**:
  - Рекурсивное разрешение зависимостей
  - Исключение ненужных пакетов
  - Follow recommends (включено/выключено)
  - Поиск зависимостей в deps-repos
  - Отчет о неразрешенных зависимостях

- **E2E - Complete Filter Pipeline**:
  - ubuntu-noble сценарий: исключение dbg/dev/doc пакетов
  - redis-jammy сценарий: сохранение特定нных версий с зависимостями
  - Полный пайплайн: include → exclude → version-keep → resolve deps

### 5. tests/unit.test.ts (7 тестов)

Юнит-тесты базовых утилит:

- **Debian Version Comparison**:
  - Сравнение простых версий
  - Обработка тильд (~)
  - Обработка эпох (1:1.0)

- **Dependency Parser**:
  - Парсинг простых зависимостей
  - Парсинг OR зависимостей (pkg1 | pkg2)

- **Filter Logic**:
  - Exclude по приоритету и имени
  - Keep specific versions

## Анализ непокрытых строк

### src/filter.ts (93.61% coverage)

Непокрытые строки:
- **68, 70-72**: Ветка обработки неявного RegExp в matchesRule (version). Требуется тест с версией без префикса `r|`, но с символами `^`, `.*`, `.+`.
- **144**: Возврат packages когда versionKeepRules пуст. Это edge case, который сложно покрыть в текущей структуре тестов.
- **202-203, 214-215**: Обработка PreDepends и Suggests в extractDependencies. Требуется тест с этими полями.
- **304, 360-361, 372**: Ветки внутри resolveDependencies при работе с deps-repos и excludedSet. Требуются сложные интеграционные тесты.

### src/parser.ts (80.85% coverage)

- **32, 34-39**: Обработка продолжения многострочных полей (начинается с пробела). Требуется тест с многострочным полем.
- **57**: Добавление последнего пакета если он есть. Edge case при парсинге.

### src/utils/debian-version.ts (59.85% coverage)

Непокрытые строки:

- **138-140, 147, 149**: Ветки сравнения строк в compareUpstream. Требуются тесты с буквенными суффиксами версий.

## Моки и изоляция

Тесты используют следующие подходы для изоляции:

- **Логгер**: Создает временные файлы логов в `./data/` с последующей очисткой.
- **E2E тесты**: Запускают реальный сервер на порту 3000 с тестовой конфигурацией.
- **Фильтры**: Используют моковые данные пакетов вместо реальных запросов к upstream.
- **Пути**: Тестируют функции без реального создания файлов.
