## Обзор

Debian Package Filter Proxy — это HTTP-прокси сервер, который фильтрует метаданные Debian/Ubuntu репозиториев перед их передачей клиенту (например, Pulp). Приложение позволяет:
- Исключать пакеты по имени, версии или приоритету (например, `-dbg`, `-doc`, `-dev`).
- Оставлять только определенные версии пакетов (например, последние 3 версии или версии, соответствующие шаблону `6.2.*`).
- Автоматически разрешать зависимости, включая поиск в других репозиториях.
- Отдавать валидные файлы `Packages.gz` с корректными хешами и опциональной GPG подписью.
- Перенаправлять запросы к `.deb` файлам на оригинальный upstream (301 Redirect).

**Технологии**: Bun, TypeScript, SQLite. Никаких внешних npm зависимостей.

## Архитектура

```
┌─────────────┐      ┌──────────────────────┐      ┌──────────────────┐
│   Pulp /    │      │  Debian Package      │      │   Upstream       │
│   Apt       │─────▶│  Filter Proxy        │─────▶│   Repository     │
│   Client    │      │  (Bun + TS + SQLite) │      │   (ubuntu.com)   │
└─────────────┘      └──────────────────────┘      └──────────────────┘
                            │
                            ├── Фильтрация Packages
                            ├── Разрешение зависимостей
                            ├── Кэширование в SQLite
                            └── 301 Redirect для .deb
```

### Компоненты
- **HTTP Server**: Обрабатывает входящие запросы, проксирует метаданные, редиректит пакеты.
- **Parser**: Парсит файлы `Packages` в формате Debian Control.
- **Filter Engine**: Применяет правила include/exclude, version-keep, разрешает зависимости.
- **Version Comparator**: Алгоритм сравнения версий Debian (порт из `aptly`).
- **Config Manager**: Загружает конфигурацию из JSON файлов.
- **SQLite Cache**: Хранит отфильтрованные пакеты и метаданные.

## Конфигурация

Конфигурация разделена на два уровня:
1. **Глобальный конфиг**: Настройки приложения.
2. **Конфиги репозиториев**: Параметры для каждого репозитория.

### Глобальный конфиг (`config/config.json`)

```json
{
  "logLevel": "info",
  "logFile": "app.log",
  "port": 8080,
  "cacheDir": "./cache",
  "syncInterval": 3600
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `logLevel` | string | Уровень логирования: `debug`, `info`, `warn`, `error`. |
| `logFile` | string | Путь к файлу лога. |
| `port` | number | Порт HTTP сервера. |
| `cacheDir` | string | Директория для кэширования файлов. |
| `syncInterval` | number | Интервал автоматической синхронизации в секундах (0 = отключено). |

### Конфиг репозитория (`config/repos/{id}.json`)

Пример: `config/repos/ubuntu-noble.json`

```json
{
  "id": "ubuntu-noble",
  "upstream": "http://ru.archive.ubuntu.com/ubuntu",
  "dist": "noble",
  "components": ["main", "restricted", "universe", "multiverse"],
  "arch": ["amd64"],
  "include": [],
  "exclude": [
    { "name": ".*-dbg$" },
    { "name": ".*-doc$" },
    { "name": ".*-dev$" },
    { "priority": ["optional", "extra"] }
  ],
  "deps": {
    "follow-recommends": false,
    "follow-suggests": false
  },
  "deps-repos": ["ubuntu-noble-updates"],
  "verify-checksums": false,
  "allow-unresolved": false
}
```

#### Обязательные поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор репозитория (используется в URL: `/r/{id}`). |
| `upstream` | string | Базовый URL оригинального репозитория. |
| `dist` | string | Дистрибутив (например, `noble`, `jammy`). |
| `components` | string[] | Компоненты репозитория (`main`, `universe`, и т.д.). |
| `arch` | string[] | Архитектуры (`amd64`, `arm64`, и т.д.). |

#### Опциональные поля

| Поле | Тип | Описание |
|------|-----|----------|
| `include` | array | Правила включения пакетов. Если пусто — включаются все. |
| `exclude` | array | Правила исключения пакетов. Применяются после include. |
| `deps` | object | Настройки разрешения зависимостей. |
| `deps.follow-recommends` | boolean | Включать ли рекомендованные пакеты (`Recommends`). |
| `deps.follow-suggests` | boolean | Включать ли предлагаемые пакеты (`Suggests`). |
| `deps-repos` | string[] | Список ID репозиториев для поиска неразрешенных зависимостей. |
| `verify-checksums` | boolean | Проверять ли контрольные суммы пакетов. |
| `allow-unresolved` | boolean | Разрешить ли наличие неразрешенных зависимостей (с предупреждением). |

### Правила фильтрации

Каждое правило в `include` или `exclude` — это объект с полями:

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | RegExp паттерн для имени пакета. |
| `version` | string | RegExp паттерн для версии пакета (опционально). |
| `priority` | string[] | Список приоритетов для исключения (например, `["optional", "extra"]`). |

#### Примеры правил

**Исключить все пакеты с суффиксом `-dbg`:**
```json
{ "name": ".*-dbg$" }
```

**Исключить пакеты с приоритетом `optional` или `extra`:**
```json
{ "priority": ["optional", "extra"] }
```

**Включить только `redis-server` версий `6.2.*`:**
```json
{ "name": "^redis-server$", "version": "^6\\.2\\..*" }
```

### Управление версиями (`version-keep`)

Позволяет оставить только определенное количество версий пакета.

```json
"include": [
  {
    "name": "redis-server",
    "version-keep": 3,
    "version": "^6\\.2\\..*"
  }
]
```

- `version-keep`: Количество последних версий, которые нужно оставить.
- `version`: RegExp паттерн для фильтрации версий (опционально).

**Логика:**
1. Находятся все пакеты с именем `redis-server`.
2. Если указан `version`, выбираются только версии, подходящие под паттерн.
3. Сортируются по убыванию версии (алгоритм Debian).
4. Оставляются первые `version-keep` версий.

## Логика фильтрации

Процесс фильтрации происходит в следующем порядке:

### 1. Загрузка пакетов
При синхронизации скачиваются файлы `Packages.gz` со всех указанных `components` и `arch`.

### 2. Применение Include
Если `include` не пуст, выбираются только пакеты, соответствующие хотя бы одному правилу.

### 3. Применение Exclude
Исключаются пакеты, соответствующие любому правилу в `exclude`.

### 4. Version Keep
Для пакетов с параметром `version-keep` оставляются только указанные версии.

### 5. Разрешение зависимостей
Для каждого оставшегося пакета:
- Анализируются поля `Depends`, `Pre-Depends`.
- Если `follow-recommends: true`, добавляются `Recommends`.
- Если `follow-suggests: true`, добавляются `Suggests`.
- Зависимости ищутся в текущем репозитории и в `deps-repos`.
- Найденные пакеты добавляются в финальный список рекурсивно.

### 6. Генерация выходных данных
- Создается отфильтрованный файл `Packages`.
- Сжимается в `Packages.gz`.
- Вычисляются хеши (MD5, SHA1, SHA256).
- Обновляется файл `Release` (если существует).
- Опционально подписывается через GPG.

## API

### GET `/r/:repo/sync`

Принудительная синхронизация репозитория.

**Пример:**
```bash
curl http://localhost:8080/r/ubuntu-noble/sync
```

**Ответ:**
```json
{
  "status": "success",
  "message": "Sync completed",
  "stats": {
    "total": 50000,
    "filtered": 45000,
    "resolved": 48000,
    "warnings": 2
  }
}
```

### GET `/r/:repo/packages/list`

Получить список отфильтрованных пакетов в формате JSON.

**Параметры запроса:**
- `name` (string): Фильтр по имени пакета (RegExp).
- `limit` (number): Максимальное количество результатов (по умолчанию 100).

**Пример:**
```bash
curl "http://localhost:8080/r/ubuntu-noble/packages/list?name=^nginx&limit=10"
```

**Ответ:**
```json
{
  "repo": "ubuntu-noble",
  "count": 10,
  "packages": [
    {
      "name": "nginx",
      "version": "1.24.0-1ubuntu1",
      "arch": "amd64",
      "size": 123456,
      "dependencies": ["libc6", "libssl3"]
    },
    ...
  ]
}
```

### GET `/r/:repo/dists/:dist/...`

Прокси запросов к метаданным репозитория (InRelease, Release, Packages.gz).

**Пример:**
```bash
curl http://localhost:8080/r/ubuntu-noble/dists/noble/main/binary-amd64/Packages.gz
```

### GET `/r/:repo/pool/...`

Редирект на оригинальный `.deb` пакет.

**Пример:**
```bash
curl -I http://localhost:8080/r/ubuntu-noble/pool/main/n/nginx/nginx_1.24.0-1ubuntu1_amd64.deb
```

**Ответ:**
```
HTTP/1.1 301 Moved Permanently
Location: http://ru.archive.ubuntu.com/ubuntu/pool/main/n/nginx/nginx_1.24.0-1ubuntu1_amd64.deb
```

## Примеры использования

### Сценарий 1: Исключение отладочных и документационных пакетов

**Цель**: Уменьшить размер зеркала, исключив `-dbg`, `-doc`, `-dev` пакеты.

**Конфиг:**
```json
{
  "id": "ubuntu-minimal",
  "upstream": "http://ru.archive.ubuntu.com/ubuntu",
  "dist": "noble",
  "components": ["main"],
  "arch": ["amd64"],
  "exclude": [
    { "name": ".*-dbg$" },
    { "name": ".*-doc$" },
    { "name": ".*-dev$" }
  ]
}
```

### Сценарий 2: Оставление только определенных версий Redis

**Цель**: Оставить только версии Redis 6.2.x (последние 2) и 8.0.x (последняя 1).

**Конфиг:**
```json
{
  "id": "redis-jammy",
  "upstream": "https://packages.redis.io/deb",
  "dist": "jammy",
  "components": ["main"],
  "arch": ["amd64"],
  "include": [
    {
      "name": "redis-server",
      "version": "^6\\.2\\..*",
      "version-keep": 2
    },
    {
      "name": "redis-server",
      "version": "^8\\.0\\..*",
      "version-keep": 1
    }
  ],
  "deps-repos": ["ubuntu-jammy"]
}
```

### Сценарий 3: Полное зеркало с исключением уязвимых версий

**Цель**: Зеркалить всё, кроме пакетов с известными уязвимостями.

**Конфиг:**
```json
{
  "id": "ubuntu-safe",
  "upstream": "http://ru.archive.ubuntu.com/ubuntu",
  "dist": "noble",
  "components": ["main", "universe"],
  "arch": ["amd64"],
  "exclude": [
    { "name": "openssl", "version": "^1\\.1\\.[0-5].*" },
    { "name": "libssl3", "version": "^3\\.0\\.0$" }
  ]
}
```

## GPG подпись

Если в системе установлена утилита `gpg`, приложение автоматически подпишет файлы `InRelease` и `Release` при синхронизации.

### Требования
- Установленный `gpg` (системная утилита).
- Наличие ключа в связке ключей GPG.

### Настройка

Приложение использует первый доступный секретный ключ в системе. Для указания конкретного ключа добавьте в глобальный конфиг:

```json
{
  "gpgKey": "YOUR_KEY_ID"
}
```

### Процесс подписи
1. После генерации `Release` файла вызывается `gpg --detach-sign`.
2. Создаются файлы `Release.gpg` и `InRelease`.
3. Подписанные файлы отдаются клиенту.

Если `gpg` не установлен или ключ не найден, подпись пропускается (с предупреждением в лог).

## Устранение неполадок

### Проблема: Неразрешенные зависимости в логе

**Причина**: Зависимость не найдена в текущем репозитории.

**Решение**:
1. Добавьте репозиторий с системными пакетами в `deps-repos`.
2. Или установите `allow-unresolved: true`, если зависимости не критичны.

**Пример:**
```json
{
  "id": "redis-noble",
  "deps-repos": ["ubuntu-noble"],
  "allow-unresolved": false
}
```

### Проблема: Пакеты не фильтруются

**Причина**: Некорректный RegExp паттерн.

**Решение**:
1. Проверьте паттерн на [regex101.com](https://regex101.com/).
2. Экранируйте специальные символы (например, `.` → `\\.`).
3. Используйте тестовый эндпоинт `/packages/list` для проверки.

### Проблема: Ошибка GPG подписи

**Причина**: Не установлен `gpg` или нет ключа.

**Решение**:
1. Установите `gpg`: `apt install gnupg`.
2. Импортируйте или создайте ключ: `gpg --gen-key`.
3. Укажите `gpgKey` в конфиге.

### Проблема: Медленная синхронизация

**Причина**: Большой размер репозитория или медленный upstream.

**Решение**:
1. Увеличьте `syncInterval` для редкой автоматической синхронизации.
2. Используйте более узкие фильтры для уменьшения количества пакетов.
3. Проверьте сетевое соединение с upstream.
